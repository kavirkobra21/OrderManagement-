# دفترچه سفارش (Order Notebook)

اپلیکیشن Native اندروید (Kotlin + Jetpack Compose + Room) برای مدیریت مشتریان و سفارش‌ها؛ ظاهر برنامه و تصویر خروجی سفارش بر اساس صفحهٔ دفترچه‌ی کاغذی (آبی پاستلی، زرد، سبز، صورتی با حباب‌ها و استیکرها) ساخته شده است.

## امکانات
- ثبت مشتری و سفارش (تاریخ شمسی خودکار، شماره فاکتور خودکار، آیتم‌ها، هزینه کل، بیعانه، باقی‌مانده)
- **تولید تصویر سفارش**: اطلاعات روی قالب دفترچه نوشته می‌شود (متن‌ها در کادرها جا می‌شوند)، ذخیره در گالری، اشتراک‌گذاری، ارسال به تلگرام
- وضعیت سفارش/پرداخت با چک‌باکس، چند عکس برای هر سفارش (رسید، سفارش، محصول نهایی، رضایت مشتری)
- سطل زباله (بازیابی کامل / حذف دائمی / خالی کردن)
- Export/Import بکاپ ZIP با بررسی سلامت و نسخه و تأیید کاربر
- ذخیره‌ی سفارش‌ها در GitHub با صف همگام‌سازی، تلگرام (ارسال و ویرایش پیام)، GitHub Updater، آفلاین‌بودن کامل بخش مشتریان و سفارش‌ها

## ساخت APK (بدون Android Studio)
1. پروژه را در GitHub پوش کنید؛ Workflow در `.github/workflows/build.yml` خودکار اجرا می‌شود.
2. APK را از **Actions → اجرای آخر → Artifacts** بردارید.
3. انتشار نسخه: یک تگ بسازید، مثلاً `git tag v1.0.1 && git push origin v1.0.1`. APK امضاشده به **Releases** اضافه می‌شود و نسخه‌ی برنامه برابر تگ است.

امضا: به‌صورت پیش‌فرض از `app/release.jks` استفاده می‌شود تا نسخه‌های بعدی روی قبلی نصب شوند. برای کلید خصوصی خودتان، Secrets زیر را در GitHub بسازید (`KEYSTORE_PATH`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`) و فایل keystore را مطابق آن قرار دهید. توصیه می‌شود برای انتشار جدی کلید پیش‌فرض را عوض کنید، چون در مخزن موجود است (و اگر عوض شود، نسخه‌های قبلی باید حذف و دوباره نصب شوند).

## ذخیره‌سازی در GitHub و همگام‌سازی
اتصال GitHub یک‌بار در **Settings → اتصال GitHub** وارد می‌شود (آدرس مخزن + Personal Access Token با دسترسی *Contents: Read and write*) و رمزنگاری‌شده روی گوشی ذخیره می‌ماند.

سفارش‌ها در همین مخزن ذخیره می‌شوند:
```
orders/
  1/  order.json  customer.json  order_image.png  payment_receipt.<ext>  images/
  2/  ...
```
- اولین سفارش پوشه‌ی `1` است و شماره‌ها افزایشی‌اند. با ویرایش سفارش همان پوشه به‌روز می‌شود (هر سفارش یک `uid` ثابت دارد، پس سفارش تکراری ساخته نمی‌شود و فایل بدون تغییر دوباره آپلود نمی‌شود).
- **آفلاین:** همه‌چیز اول در دیتابیس محلی ذخیره می‌شود و کارها در صف *Pending Sync* می‌مانند. با وصل شدن اینترنت، آپلود به GitHub و ارسال/ویرایش تلگرام خودکار انجام می‌شود؛ کارهای ناموفق دوباره تلاش می‌شوند.
- **تعارض:** اگر نسخه‌ی GitHub جدیدتر از نسخه‌ی محلی باشد، روی آن نوشته نمی‌شود و نسخه‌ی GitHub گرفته می‌شود (جدیدترین `updatedAt` برنده است).
- **مهم – حریم خصوصی:** مخزن باید **Private** باشد. اگر مخزن Public باشد برنامه از آپلود اطلاعات مشتریان خودداری می‌کند.
- حذف دائمی مشتری از سطل زباله، نسخه‌ی موجود در GitHub را پاک نمی‌کند (به‌عنوان پشتیبان می‌ماند).
- Workflow بیلد برای push روی `orders/**` و `config/**` اجرا نمی‌شود.

## تلگرام (فقط از طریق GitHub Actions)
برنامه هیچ چیزی را مستقیم به تلگرام نمی‌فرستد. بعد از Push شدن سفارش به `orders/<n>/`، Workflow با نام **Telegram Notify** (`.github/workflows/telegram.yml`) اجرا می‌شود و با `.github/scripts/telegram_notify.py` پیام و عکس‌ها را می‌فرستد.

**راه‌اندازی (یک‌بار):** در GitHub → Settings → Secrets and variables → Actions → *New repository secret*:

| Secret | مقدار |
|---|---|
| `BOT_TOKEN` | توکن ربات از BotFather |
| `CHAT_ID` | شناسه‌ی چت شما |

ربات را در تلگرام **Start** کنید. (برای خود Workflow به توکن GitHub اضافه نیاز نیست؛ از `GITHUB_TOKEN` داخلی استفاده می‌کند. توکن GitHub که در برنامه وارد می‌شود فقط روی گوشی، رمزنگاری‌شده، می‌ماند.)

- متن سفارش (شناسه، مشتری، تلفن، آدرس، **آیتم‌ها با قیمت**، جمع‌ها، وضعیت)، تصویر دفترچه و **همه‌ی عکس‌های سفارش** (رسید، سفارش، محصول، رضایت) ارسال می‌شود.
- **بدون ارسال تکراری:** وضعیت ارسال در `orders/<n>/telegram.json` (message_id و SHA فایل‌ها) ذخیره می‌شود. اجرای مجدد Action چیزی نمی‌فرستد. با تغییر سفارش همان پیام ویرایش می‌شود؛ عکس جدید فقط یک‌بار ارسال می‌شود؛ تغییر تصویر دفترچه، عکس قبلی را ویرایش می‌کند.
- **خطا و تلاش مجدد:** روی خطای موقت (شبکه، 5xx، 429) چند بار با تأخیر تلاش می‌شود. خطای دائمی (مثلاً Start نشدن ربات) در لاگ Action دیده می‌شود و Workflow هر ساعت دوباره تلاش می‌کند.
- **Telegram Settings** در برنامه: زبان پیام‌ها و روشن/خاموش بودن ارسال (فایل `config/notify.json`) و دکمه‌ی **Test Connection** که یک پیام آزمایشی را از طریق Action می‌فرستد (توکن GitHub باید دسترسی *Actions: Read and write* هم داشته باشد).
- سفارش‌هایی که نسخه‌ی قبلی برنامه خودش ارسال کرده بود، با همان `message_id` ادامه می‌یابند و دوباره ارسال نمی‌شوند.
- مبالغ به تومان، با ارقام انگلیسی و کاما.

## ورود سفارش با Paste
صفحه‌ی اصلی → **ورود سفارش با Paste**: دکمه‌ی «کپی قالب فرم» قالب را برای مشتری کپی می‌کند. پاسخ او را Paste کنید؛ نام، تلفن، آدرس، نکات و آیتم‌ها استخراج می‌شوند (فرمت‌های کمی متفاوت هم تا حد امکان تشخیص داده می‌شوند، فیلد خالی خطا نمی‌دهد). برای هر آیتم فیلد قیمت خالی است. چیزی تا «تأیید و ثبت نهایی» ذخیره نمی‌شود؛ مشتری با همان شماره‌ی تلفن دوباره ساخته نمی‌شود.

## آیتم‌ها و قیمت
قیمت هر آیتم با کامای زنده و «تومان» وارد می‌شود (عدد واقعی ذخیره می‌شود). جمع آیتم‌ها و هزینه‌ی کل خودکار به‌روز می‌شوند. بخش «سفارش‌ها» در صفحه‌ی دفترچه، لیست سفارش‌ها و پیام تلگرام هر آیتم را با قیمتش نشان می‌دهد.

## بکاپ
- **GitHub Backup:** *Backup to GitHub* همه‌ی سفارش‌ها را در صف آپلود می‌گذارد؛ *Restore from GitHub* ابتدا تعداد سفارش‌ها و زمان آخرین بکاپ را نشان می‌دهد و پس از تأیید شما، اطلاعات و تصاویر را با داده‌های فعلی ادغام می‌کند (نسخه‌ی جدیدتر برنده است، چیزی حذف نمی‌شود).
- **Export / Import (ZIP):** فایل ZIP شامل مشتریان، سفارش‌ها، تصاویر، سطل زباله و تنظیمات است (`manifest.json`، `data.json`، `attachments/`). Import ابتدا سلامت و نسخه را بررسی می‌کند و پس از تأیید، همه‌چیز را جایگزین می‌کند. فایل شامل توکن‌هاست؛ در جای امن نگه دارید.

## GitHub Updater
Settings → GitHub Updater فقط نسخه را بررسی می‌کند و از همان مخزن/توکن ذخیره‌شده در «اتصال GitHub» استفاده می‌کند (برای مخزن Private توکن لازم است). «Check for Updates» آخرین Release را می‌خواند، تغییرات را نشان می‌دهد و APK را با درصد پیشرفت دانلود و با نصب‌کنندهٔ اندروید نصب می‌کند. داده‌ها هنگام آپدیت پاک نمی‌شوند (applicationId و کلید امضا ثابت است). بار اول اندروید اجازه «نصب از این منبع» را می‌خواهد.

## یادداشت‌ها
- فونت: از فونت فارسی سیستم استفاده می‌شود. برای ظاهر دست‌نویس‌تر، یک فونت (مثلاً در `res/font`) اضافه و در `NotebookPage` به‌جای `Typeface.DEFAULT` استفاده کنید.
- موقعیت دقیق کادرها در `NotebookPage.kt` (مختصات ۱۰۰۰×۱۴۰۰) قابل تنظیم است.

## انتشار خودکار در Kavir Store
بعد از هر Release موفق، job `publish-store` در `build.yml`:
1. همان APK امضاشده را در ریپوی **عمومی** `kavirkobra19/OrderNotebook-Releases` منتشر می‌کند (ریپوی خصوصی سفارش‌ها دست‌نخورده می‌ماند؛ یادداشت Release عمداً ساده است تا عنوان commitها بیرون نرود).
2. اگر برنامه هنوز در `catalog/sources.json` ریپوی KavirStore نیست، یک‌بار ثبتش می‌کند؛ در غیر این صورت رکورد را تغییر نمی‌دهد (بدون تکرار).
3. به KavirStore اعلام می‌کند Sync کند. نام package، versionCode، نسخه، minSdk و لینک دانلود را خود فروشگاه از APK استخراج می‌کند و همان رکورد به‌روز می‌شود.

**لازم است:** Secret به نام `KAVIR_STORE_TOKEN` (توکن fine-grained حساب `kavirkobra19` با *Contents: Read and write* روی دو ریپوی `KavirStore` و `OrderNotebook-Releases`)، و ساخت ریپوی عمومی `OrderNotebook-Releases` (می‌توان با Variableهای `KAVIR_STORE_APP_REPO` و `KAVIR_STORE_REPO` نام‌ها را عوض کرد). بدون Secret این مرحله فقط هشدار می‌دهد و بیلد خراب نمی‌شود. versionCode همان شماره‌ی اجرای CI است (همیشه افزایشی) و کلید امضا ثابت است.

## نسخه‌ی جدید: ریپوی جدا برای سفارش‌ها، Secretها از داخل برنامه
- **دو ریپوی مستقل:** ریپوی برنامه فقط کد و Build دارد. هر کاربر ریپوی Private خودش را در «اتصال GitHub» می‌دهد و سفارش‌ها فقط آن‌جا ذخیره می‌شوند. به‌روزرسانی برنامه چیزی از سفارش‌ها را پاک یا بازنویسی نمی‌کند (دیتابیس با Migration نسخه ۳ به‌روز می‌شود).
- **Telegram Settings:** Bot Token و Chat ID را وارد و «ذخیره و اتصال» را بزنید. برنامه ریپوی سفارش را بررسی می‌کند (در صورت اجازه‌ی توکن Private می‌سازد)، فایل‌های `.github/workflows/telegram.yml` و `.github/scripts/telegram_notify.py` را می‌سازد یا به‌روز می‌کند (بدون تکرار) و مقادیر را رمزنگاری‌شده (sealed box) در Secrets `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` ثبت و وجودشان را تأیید می‌کند. مقدار این رازها روی گوشی ذخیره یا لاگ نمی‌شود.
- **دسترسی‌های توکن GitHub (fine-grained، فقط روی ریپوی سفارش):** Contents، Workflows و Secrets هر سه *Read and write*؛ Actions *Read and write* برای دکمه‌ی Test Connection. ساخت خودکار ریپو فقط با توکنی ممکن است که اجازه‌ی ساخت مخزن دارد؛ وگرنه ریپو را خودتان (Private) بسازید.
- **ویرایش متن سفارش:** در تنظیمات؛ ویرایش، پیش‌نمایش، بازگردانی پیش‌فرض و متغیرهای `{name} {quantity} {items} {total} {id} {postal_code} {phone} {address} {date} {time} {order_id}`. متن در «کپی قالب» (Paste) و «کپی متن سفارش» (صفحه‌ی سفارش) استفاده می‌شود.
- **فیلدهای جدید:** تعداد (روی سفارش)، آیدی و کد پستی (روی مشتری)؛ آدرس و تلفن حفظ شده‌اند.
